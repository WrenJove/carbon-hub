# carbon-hub（个人碳账本聚合器）

> **关于本项目的定位，先声明一件事。**
>
> 这是**赛前准备的通用工具**，不是任何比赛的参赛作品。它是一套把不同来源的能源数据
> 归一到同一碳核算口径、并出具可校验凭证的工具集。
> 依据南通大学 AI for Green 挑战赛细则第十条，"赛前准备的通用工具和公开代码可以使用，
> 但须说明来源"，此处如实说明。
>
> 它天然是数据无关的：换一个数据源只需要新增一个适配器，核算内核一行不用改。

一句话定位：**各平台的碳数据，你不用二选一——这个程序把它们的账合成一份你能带走的碳账本。**

面向"AI for Green"B 赛道（能源 / 绿色交通 / 碳管理）。赞助方中碳普惠云的主业就是个人碳账户，
他们自家 AI 公开承认的行业痛点是：各碳普惠平台数据不互通、核算标准不一致、存在数据孤岛。
本项目直接对着这个痛点做。

---

## 一、为什么先做接口，而不是先去搞数据

个人碳数据都锁在别人的 App 里：蚂蚁森林、各家银行碳账户、各地碳普惠平台，一个开放接口都没有。
想拿数据只能靠爬虫或模拟登录——违反用户协议、24 小时做不出来、被评委一问就穿帮。

所以把顺序倒过来：**先把接口定死，数据源接一个算一个。**

- 演示的完整度不再取决于你能接几家平台，而取决于接口设计得好不好；
- 以后每多一个数据源，只是多写一个适配器，内核一行不改；
- "统一的接口规范"本身就是行业在喊的东西，接口做扎实 = 作品的加分项，不是权宜之计。

三条铁律：

1. 只处理用户**自己导出 / 自己拍摄 / 自己手输**的数据；
2. 不存账号密码，不代登录第三方平台，不碰登录态接口；
3. 能力声明如实标注——已接入就说已接入，占位就说占位。

## 二、五层结构

| 层 | 名字 | 输入 → 输出 | 谁负责 |
|---|---|---|---|
| L1 | 采集 | `RawInput` → `ActivityRecord[]` | 各数据源的 Adapter |
| L2 | 归一 | 单位、分类、置信度统一 | 同上（在 Adapter 内完成） |
| L3 | 核算 | `ActivityRecord` × `EmissionFactor` → `EmissionRecord` | 内核，一套 |
| L4 | 记账 | → `CarbonLedger`（分范围、分类目、可追溯） | 内核，一套 |
| L5 | 出具 | → `CarbonPassport`（可对外交换的凭证） | 内核，一套 |

契约见 [types.ts](types.ts)，逐条说明见 [INTERFACES.md](INTERFACES.md)。

## 三、适配器状态：这是演示的核心装置

每个数据源声明自己的 `status`，界面据此显示"已接入 / 可接入 / 待接入"：

- `connected`：真的能跑。比赛现场用两个——**支付宝/微信账单 CSV** 和 **电费单据拍照 OCR**。
- `available`：接口留好、等对接。
- `planned`：只占位，展示架构的延展性。

演示时**如实标注**，别把占位说成已接入。评委问"蚂蚁森林的数据你怎么拿的"，正确答案是
"拿不到，所以我定义了适配器接口，等它开放；我现场演示的是用户自己能导出的那两类数据"。

## 四、24 小时演示脚本

1. 拖进一份支付宝账单 CSV → 系统自动归类成出行、外卖、电费、购物几类活动；
2. 拍一张电费单照片 → 多模态模型读出用电量，抽成活动记录；
3. 一键核算 → 出一份分范围（Scope 1/2/3）、分类目、可追溯的碳账本；
4. 导出 `碳护照`（单个 JSON）→ 切到"第三方视角"用另一段程序把它读进来，证明凭证是可交换的；
5. 收尾一页：把适配器清单铺开，讲"接一个是一个"的延展路径。

## 五、评分点对照

| 评分维度 | 本项目的落点 |
|---|---|
| 项目改进成效 | 把 N 个平台各自为政的账，合成一份可比、可带走的账；互通成本从 N×N 降到 N |
| 创新程度 | 适配器契约 + 统一核算层 + 可交换的碳数据凭证（对着"统一格式/接口规范"提方案） |
| 方案有效性 | 真实数据（账单 CSV + 拍照）现场跑通，不是 PPT |
| 技术落地实现 | 只依赖现成大模型 API，无需训练；数据源按需增删 |
| 成果演示质量 | 一条数据从"原始素材"到"可交换凭证"走完全程，可视化账本收尾 |

## 六、给 Codex 的施工单（以后写代码时看这里）

按这个顺序做，每一步都能单独跑通：

1. 按 [types.ts](types.ts) 建类型，先把 L3/L4/L5 内核写出来，用 [fixtures/factors_seed.csv](fixtures/factors_seed.csv)
   当因子库，输入用手写的 `ActivityRecord[]`，先跑通"活动 → 账本 → 凭证"。
2. 写 `AlipayBillAdapter`，用 [fixtures/alipay_bill_sample.csv](fixtures/alipay_bill_sample.csv)
   当测试样本（注意账单是 GBK 编码，中文列头要按列名映射，不要按列号）。
3. 写 `UtilityBillAdapter`（拍照 → 多模态模型 → 用电量），置信度低于阈值时要标出来。
4. 加一个 `MockAdapter` 生成合理假数据，把 `planned` 的平台在界面上"点亮"，用于演示架构。
5. 最后套一个最小界面（Streamlit / Gradio 都行）：上传区 + 账本看板 + 导出凭证按钮。

验收标准：给定一份真实账单 CSV 和一张电费单照片，能自动产出 `CarbonPassport`，
且每一条排放都能回溯到具体活动记录和因子来源（`factorId` 有据可查）。
